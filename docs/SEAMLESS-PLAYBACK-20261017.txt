BLACKBOX CONTINUOUS PLAYBACK VALIDATION
October 17, 2026 - 2.0.0-preview.8

IMPLEMENTATION
Compatible completed MKV segments are exposed as one seekable Matroska input.
A bounded structural index supplies retimed cluster headers and keyframe cues;
encoded video/audio blocks are read unchanged from the original source ranges.
VLC keeps one input, decoder, video surface, and playback clock across joins.
There is no merged recording on disk, re-encode, second decoder, or video-frame
copy. Only the current source file stays open. Preparation is cancellable and
runs outside the UI thread; review close releases callbacks, stream, and leases.

LIMITS
Continuous input currently covers finalized, compatible native/FFmpeg MKV
layouts. Different codecs/track layouts, unsupported containers, and time-shift
following retain per-file playback; those paths are not advertised as gapless.
Actual missing frames, capture pauses, or black frames already encoded in source
files cannot be recovered. Original source timestamps/relative A/V timing are
preserved. This is not a four-hour playback soak or a guarantee for every codec.

REPRODUCTION
Use --playback-transition-smoke with an isolated BLACKBOX_DATA_DIRECTORY.
Configuration includes Sources and Output; optional Durations supplies actual
recording timeline durations. SaveVirtualInput is test-only and writes a sample
virtual file for FFmpeg verification, not part of normal review.
Local reports and fixtures: artifacts\seamless-20261017.
